# SmartAgent 项目复盘

## 1. 项目背景与目标

面向「Agent 技术工程师」岗位要求（熟悉大模型应用与 Agent 框架、具备工具调用/记忆模块/提示词工程理解、Python 能力），独立完成一个 **0-1 落地** 的通用 Agent：能知识问答、自主调用工具、记住用户关键信息，并提供 CLI 与 Web Demo 双入口。

## 2. 结果概览

| 项 | 结果 |
|---|---|
| 交付形态 | 可运行的 Agent（CLI + Web Demo），代码约 900 行，无黑盒依赖 |
| 核心能力 | 工具调用循环 / 长期记忆 / 多会话隔离 / 可选联网 |
| 测试 | 图循环、工具调用去重、记忆跨轮注入、会话隔离 全部通过（无网络 mock） |
| 时间 | 个人 1 天内完成设计 + 开发 + 验证 |

## 3. 过程复盘

### 3.1 做得好的

1. **手写状态机而非黑盒**：不直接用 `create_react_agent`，自己定义节点/条件边/记忆 reducer，对 Agent 原理理解到位，答辩讲得清；
2. **记忆设计成显式机制**：用 `facts` + `remember_fact` 工具 + 系统提示词注入，形成"写→存→注入→用"闭环。相比"全部塞上下文"，这种设计 token 更省、可解释、可迁移；
3. **两级接入一次开发**：把推理收敛为统一事件流（tool_start/tool_result/token/done），CLI 与 Web 复用同一套，避免逻辑分叉；
4. **防坑前置**：计算器 AST 白名单、工具异常隔离、recursion_limit 上限，规避了"Agent 失控/死循环/任意代码执行"三大常见问题。

### 3.2 踩过的坑与解法

| 问题 | 根因 | 解法 |
|---|---|---|
| 开发早期工具调用记录重复出现 | `stream_mode="values"` 每步携带全量历史，遍历时把旧消息重复计入 | 改 `stream_mode="updates"` 只消费增量事件，工具轨迹/回复均精确 |
| **模型"口头记住"却不调工具** | 小模型对 `remember_fact` 这类"软触发"工具调用决策不稳定：同样语义 3 次只成功 1 次，只是回答"我记住了"但 `facts` 为空 | ① 提示词把"建议调用"改为强约束（"必须立刻调用，只说记住了等于没记住"）；② 升级模型到 `glm-5.3-flash`，实测工具调用 3/3 稳定 |
| **新会话编造用户身份** | 无任何记忆/上下文时，模型仍回答"您之前提到自己是前端工程师"（幻觉） | 系统提示词新增"严禁编造"约束：无事实支撑必须回答"我不清楚"，且只有被记住或本轮亲口说明的信息才可用；实测已修正 |
| 初版把所有工具调用结果无差别累加 | 未区分"执行结果"与"待记忆事实"两类数据 | tools 节点显式将 `remember_fact` 参数抽取到 `facts` reducer，与 messages 分离管理 |
| 模型偶尔幻觉编造实时信息 | 未做工具边界约束 | 系统提示词明确"需要外部/实时信息必须调用 web_search，不编造" + Tavily 可选注册 |
| Web 端复述整段消息而非流式 | 首版串行返回体验差 | FastAPI 改 SSE 事件流，前端逐事件渲染"调了什么工具→中间结果→最终答案" |

### 3.3 待改进 / 已知不足

1. 记忆目前为进程内（InMemorySaver），重启即失；下一步接 SQLite/Postgres Checkpointer 做持久化；
2. 未做评测集：只有功能冒烟测试，缺少对"工具选择准确率 / 记忆命中率"的量化评估；
3. 单模型单 Agent，尚未支持多 Agent 协作与人工审批断点；
4. Web 端 token 为整段推送，未做逐 token 打字机效果（对 SSE 而言成本很低，后续补上）。

## 4. 可复用经验

- **Agent = 状态机 + 工具 + 记忆 + 提示词**，四要素各司其职；先把图状态设计清楚再写代码，事半功倍；
- 记忆与上下文要分离：全部塞上下文的"伪记忆"在长会话与多会话场景必崩，显式事实存储是更稳的架构取向；
- 事件化输出（面向 stream 编程）比一次性返回值更利于前后端协作与可观测性。

## 5. 如果重新做，会怎么改

1. 先用 Mermaid 把图/状态/边画完整再编码（本次边写边补，浪费少量返工）；
2. 记忆层直接用 `langgraph.checkpoint` 全家桶 + 消息摘要，减少自研 reducer；
3. 补一个工具选择 mock 评测，量化召回与误调率；
4. 直接上 FastAPI + SSE + 前端打字机效果，一步到位。
